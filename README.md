\# WorkSpace — Корпоративное рабочее место сотрудника (C# / WinForms)



Автономное десктопное приложение для работы в закрытом контуре Windows через общую сетевую папку (SMB) без выделенного сервера, СУБД и интернета.



\## Жесткие технические ограничения (ОБЯЗАТЕЛЬНО К СОБЛЮДЕНИЮ ДЛЯ ИИ-АГЕНТОВ)



1\. \*\*Платформа и компиляция:\*\* Строго \*\*.NET Framework 4.x\*\* (синтаксис C# 5). Проект собирается \*\*без Visual Studio, MSBuild, `.csproj` и `.sln`\*\* через нативный компилятор Windows `C:\\Windows\\Microsoft.NET\\Framework64\\v4.0.30319\\csc.exe` запуском скрипта `build.bat`.

2\. \*\*Запрет на внешние зависимости:\*\* Не использовать NuGet-пакеты и сторонние библиотеки (никаких `Newtonsoft.Json`, `Dapper`, `EF`, `MaterialSkin`). Разрешены только стандартные сборки .NET Framework (`System.Windows.Forms.dll`, `System.Drawing.dll`, `System.Web.Extensions.dll`, `System.Data.dll`).

3\. \*\*Кодировка:\*\* Все `.cs` и `.bat` файлы должны сохраняться строго в \*\*UTF-8\*\* (в `build.bat` используется флаг `/utf8output`).

4\. \*\*Архитектура запуска:\*\* Сотрудники запускают `WorkSpace.exe` из общей сетевой папки. При старте программа сама копирует себя в `%TEMP%\\WorkSpaceApp` и перезапускается оттуда с флагом `--local "<путь\_к\_сетевой\_папке>"`, чтобы не блокировать обновление сетевого `.exe`. Повторный запуск `.exe` разворачивает уже открытое окно из трея через `EventWaitHandle`.



\## Структура проекта



```text

WorkSpace/

├── build.bat                         # Скрипт компиляции всех файлов из src\\ в WorkSpace.exe

├── app.ico                           # Иконка исполняемого файла

├── data/                             # Папка общих баз данных (не попадает в Git)

│   ├── team.json                     # Гибридный файл: открытый AllowedLogins + зашифрованный EncryptedData

│   ├── tasks.json                    # Зашифрованная база трекера задач (AES-256)

│   └── registries.json               # Зашифрованная база динамических реестров (AES-256)

└── src/

&nbsp;   ├── Program.cs                    # Точка входа, самокопирование в %TEMP%, Mutex, глобальный перехват ошибок

&nbsp;   ├── Core/

&nbsp;   │   ├── AppConfig.cs              # Определение папки data\\ и логина (Environment.UserName)

&nbsp;   │   ├── CryptoService.cs          # AES-256 шифрование; ключ формируется из отсортированного списка AllowedLogins + соль

&nbsp;   │   ├── NetworkStorage.cs         # Потокобезопасное чтение/запись JSON с блокировкой (.lock) и атомарной заменой (File.Replace)

&nbsp;   │   └── IWorkspaceModule.cs       # Интерфейс для всех вкладок приложения

&nbsp;   ├── UI/

&nbsp;   │   ├── MainForm.cs               # Главное окно, вкладки модулей, сворачивание в трей, таймер синхронизации (3 сек)

&nbsp;   │   └── IconHelper.cs             # Программная генерация иконки для окна и трея

&nbsp;   └── Modules/

&nbsp;       ├── Tasks/                    # Модуль 1: Совместный трекер задач

&nbsp;       ├── Registries/               # Модуль 2: Универсальный конструктор табличных реестров + экспорт в CSV

&nbsp;       └── Team/                     # Модуль 3: Управление командой, ролями (Администратор / Редактор / Наблюдатель) и ключами

```



\## Правила добавления нового функционала (Модулей)



1\. Каждый новый раздел создается в отдельной папке `src/Modules/<ModuleName>/`.

2\. Главный контрол модуля наследуется от `UserControl` и реализует интерфейс `IWorkspaceModule` (`Title`, `View`, `RefreshData()`).

3\. Подключение модуля выполняется добавлением его экземпляра в список `modules` внутри `src/Program.cs`.

4\. Вся работа с файлами в `data/` идет \*\*только\*\* через `NetworkStorage` (`Read<T>`, `Update<T>`, `Overwrite<T>`). Прямая запись через `File.WriteAllText` запрещена во избежание повреждения данных при одновременной работе сотрудников.

5\. Все действия изменения/удаления данных должны учитывать права текущего пользователя через `AccessService` (`IsAdmin()`, `CanEditContent()`).
